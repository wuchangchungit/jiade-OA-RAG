# 接口与消息契约设计文档

## 1. 概述与全局约定

本文档定义了“基于 AI Agent 的多轮对话系统”的前后端交互 API、流式通信协议以及内部组件（如 LangGraph 与 Tool）之间的消息契约。

### 1.1 传输协议与基准路径

* **传输协议**：HTTPS (HTTP/1.1 与 HTTP/2)
* **流式传输**：Server-Sent Events (SSE)
* **API 基础路径**：`/api/v1`

### 1.2 鉴权机制

系统采用 HTTP Bearer Token 机制。用户登录成功后，前端需在后续所有受保护 API 请求的 Header 中带上：
`Authorization: Bearer <access_token>`

### 1.3 统一 JSON 响应结构

对于标准的同步非流式 HTTP 请求，统一返回如下 JSON 结构：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {}
}

```

**通用状态码说明：**

* `200`：成功
* `400`：请求参数错误（如验证码错误、格式不支持）
* `401`：未授权或 Token 已过期
* `500`：服务器内部错误（可通过后台日志排查）

## 2. 身份认证接口

### 2.1 获取图形验证码

* **请求路径**：`GET /api/v1/auth/captcha`
* **请求说明**：前端渲染登录页时调用，生成新的图形验证码。
* **响应 Payload**：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "captcha_id": "cap_8f9a2b1c-3d4e-5f6a",
    "image_base64": "data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAA..."
  }
}

```

### 2.2 用户登录

* **请求路径**：`POST /api/v1/auth/login`
* **请求 Header**：`Content-Type: application/json`
* **请求 Payload**：

```json
{
  "username": "admin",
  "password": "your_secure_password",
  "captcha_id": "cap_8f9a2b1c-3d4e-5f6a",
  "captcha_code": "4X8Y"
}

```

* **响应 Payload**：

```json
{
  "code": 200,
  "message": "登录成功",
  "data": {
    "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "token_type": "bearer",
    "expires_in": 7200
  }
}

```

### 2.3 退出登录

* **请求路径**：`POST /api/v1/auth/logout`
* **请求 Header**：`Authorization: Bearer <access_token>`
* **响应 Payload**：

```json
{
  "code": 200,
  "message": "已成功注销",
  "data": null
}

```

## 3. 知识库与文档管理接口

### 3.1 上传文档

* **请求路径**：`POST /api/v1/documents/upload`
* **请求 Header**：`Content-Type: multipart/form-data`
* **请求参数**：
* `file`: 二进制文件数据（只支持 `.md`, `.doc`, `.docx`）


* **响应 Payload**：

```json
{
  "code": 200,
  "message": "文件上传成功并已开始索引",
  "data": {
    "document_id": "doc_10293847",
    "file_name": "company_handbook.md",
    "file_size": 1048576,
    "status": "indexed"
  }
}

```

### 3.2 获取已加载文档列表

* **请求路径**：`GET /api/v1/documents/list`
* **响应 Payload**：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "documents": [
      {
        "document_id": "doc_10293847",
        "file_name": "company_handbook.md",
        "upload_time": "2026-05-20T10:30:00Z",
        "status": "ready"
      }
    ]
  }
}

```

## 4. Agent 多轮对话接口

### 4.1 创建新对话会话

* **请求路径**：`POST /api/v1/chat/session/new`
* **响应 Payload**：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "session_id": "sess_99887766-5544-3322"
  }
}

```

### 4.2 异步流式多轮对话 (Core API)

* **请求路径**：`POST /api/v1/chat/stream`
* **请求 Header**：
* `Content-Type: application/json`
* `Accept: text/event-stream`


* **请求 Payload**：

```json
{
  "session_id": "sess_99887766-5544-3322",
  "message": "请问员工休假制度中的年假申请流程是怎样的？"
}

```

* **响应形式**：Server-Sent Events (SSE) 文本流，每条数据由 `event` 与 `data` 构成。

## 5. 消息契约与数据流结构

### 5.1 SSE 流式事件契约 (Frontend <-> Backend)

| 事件类型 (event) | 触发时机 | data 结构与说明 |
| --- | --- | --- |
| `token` | LLM 生成文本片段 | `{"content": "根据"}` （增量打字机片段） |
| `tool_start` | Agent 判定需要调用 `ems_handbook_tool` | `{"tool": "ems_handbook_tool", "query": "年假申请流程"}` |
| `tool_end` | `ems_handbook_tool` 执行完毕 | `{"tool": "ems_handbook_tool", "status": "success"}` |
| `error` | 对话过程中发生内部错误 | `{"error_code": 5001, "message": "向量数据库检索超时"}` |
| `done` | 对话完整结束 | `{"session_id": "sess_99887766-5544-3322", "finish_reason": "stop"}` |

**SSE 数据流推送示例：**

```text
event: tool_start
data: {"tool": "ems_handbook_tool", "query": "年假申请流程"}

event: tool_end
data: {"tool": "ems_handbook_tool", "status": "success"}

event: token
data: {"content": "根据"}

event: token
data: {"content": "公司员工手册，"}

event: token
data: {"content": "年假申请流程如下..."}

event: done
data: {"session_id": "sess_99887766-5544-3322", "finish_reason": "stop"}

```

### 5.2 Tool 消息契约 (`ems_handbook_tool`)

`ems_handbook_tool` 是由 LlamaIndex 检索逻辑封装、专供 LangGraph 调用的 Agent 工具。

#### 工具输入 Schema (JSON Schema)

```json
{
  "type": "object",
  "properties": {
    "query": {
      "type": "string",
      "description": "针对员工手册或新材料相关文档的检索关键词或自然语言问题"
    }
  },
  "required": ["query"]
}

```

#### 工具输出 Schema

```json
{
  "status": "success",
  "retrieved_nodes": [
    {
      "text": "第三章 休假管理...员工按工龄享受带薪年假，需提前3天在系统提交...",
      "score": 0.892,
      "metadata": {
        "file_name": "employee_handbook.md",
        "page_node": 12
      }
    }
  ]
}

```

### 5.3 LangGraph Agent State 契约

LangGraph 在内部管理多轮对话状态时采用如下强类型状态对象（`AgentState`）：

```python
from typing import TypedDict, Annotated, Sequence
from langchain_core.messages import BaseMessage
import operator

class AgentState(TypedDict):
    # 历史消息列表，通过 append 操作追加
    messages: Annotated[Sequence[BaseMessage], operator.add]
    # 当前会话标识
    session_id: str
    # 最近一次调用工具的名称与参数
    current_tool_call: dict
    # RAG 检索返回的上下文
    retrieved_context: str

```

## 6. 错误码规范

为方便前端提示及后台排查日志，对业务逻辑异常设定统一错误码表：

| 错误码 | 错误含义 | 排查建议与说明 |
| --- | --- | --- |
| `1001` | 验证码错误或已过期 | 检查 Redis/Session 中的 captcha_id 匹配状态 |
| `1002` | 用户名或密码错误 | 数据库查询用户凭证无匹配结果 |
| `2001` | 不支持的文件格式 | 仅允许上传 `.md`, `.doc`, `.docx` 格式文档 |
| `2002` | RAG 索引构建失败 | 检查 LlamaIndex 解析与 Chroma 持久化连接 |
| `3001` | LangGraph 运行异常 | 查看 Langfuse Trace 堆栈排查 Agent 节点错误 |
| `3002` | LLM API 调用失败或超时 | 检查 API KEY 配置及网络外网可达性 |
